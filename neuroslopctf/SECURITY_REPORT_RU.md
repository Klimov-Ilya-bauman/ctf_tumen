# Отчёт по исправлению NeuroslopCTF

## Результат и область проверки

Исправлен сервис в текущем каталоге: сервер, общий TypeScript-фреймворк,
зависимости фронтенда и конфигурация запуска. Приоритет — attack–defence:
предотвращение чтения чужих флагов/наград, обхода авторизации и изменения чужих
данных. Существующие API-маршруты и основные DTO сохранены. JSON и URL-encoded
формы поддерживаются; multipart остаётся для загрузки файлов. Значения флагов,
наград и пароли пользователей не подменялись.

Проверены контроллеры, модели, сервисы, аутентификация, ORM/SQL, HTTP-слой,
клиентский рендеринг и зависимости. Первичный независимый обзор подтвердил
критические ошибки политик; повторный обзор выявил дополнительные граничные
случаи, которые исправлены и покрыты регрессиями. Отсутствие абсолютно всех
возможных уязвимостей конечным аудитом доказать нельзя; ниже перечислены
конкретные найденные проблемы и проверенные исправления.

## Найденные уязвимости

### Критические и высокие

| № | Проблема и последствия | Где исправлено |
|---|---|---|
| 1 | **SQL-инъекция в ORM.** Строки без экранирования попадали в запросы, включая INSERT JSON и UPDATE. Можно было обходить WHERE авторизации, читать/менять БД; старый DB-пользователь был superuser. Все значения ORM теперь передаются PostgreSQL-параметрами, отдельными для каждого запроса. Неподдерживаемые типы/нечисловые числа отклоняются. | `packages/thingamajig/src/{foundry,engine,spigot}.ts` |
| 2 | **Обход пароля по его производному ключу.** `verifyPassword` принимал Base64-часть хеша как готовый пароль. При утечке `passwordHash` не требовался подбор исходного пароля. Эта ветка удалена; проверяется только scrypt с допустимыми длинами соли/ключа. | `apps/server/src/auth/passwords.ts` |
| 3 | **Глобальные роли вместо ролей соревнования.** Выбор membership не связывался с текущим competitionId. Владение своим соревнованием давало права на чужие. Добавлена обязательная корреляция. | `apps/server/src/models/competition.ts` |
| 4 | **Закрепление соревнования давало ownership.** Соревнование наследовало роль `owner` из пользовательского pin. Удалено наследование авторизации от закладок. Закладки остаются закладками. | `apps/server/src/models/competition.ts` |
| 5 | **Самоповышение/саморазбан участника.** Субъект membership объявлялся её `owner`, а UPDATE проверял эту роль. Удалён конфликт ролей; обработчик проверяет право управлять именно целевым участником и допустимость выдаваемой роли. Администратор не может назначать других администраторов в обход владельца. | `models/membership.ts`, `controllers/members.ts` |
| 6 | **Утечка флагов и reward tokens через revisions.** Листинг выполнял все чтения под `sudo` и требовал только входа. Оба endpoint истории теперь проходят обычную авторизацию соревнования/задачи и требуют `task.view_secrets`. | `controllers/task-revisions.ts` |
| 7 | **Вложенные запросы обходили read-политики.** ORM защищал только корневой statement. Read-политики теперь применяются к вложенным запросам приложения. Доверенные запросы внутри самих политик отделены, чтобы не получить бесконечную рекурсию. | `packages/thingamajig/src/engine.ts` |
| 8 | **Обход competition binding API-токена.** Глобальный `/solves/mine` раскрывал награды из других соревнований; join/revisions также обходили общий helper. Добавлены проверка binding и фильтрация глобальных коллекций. Bound-token не может создавать новое соревнование. | `auth/middleware.ts`, `services/http.ts`, `controllers/{solves,competitions,members,task-revisions}.ts` |
| 9 | **Забаненный участник продолжал читать будущие награды команды.** Командный доступ не учитывал статус membership, при бане сохранялся teamId. Выборки требуют active participant; бан/смена роли отделяют пользователя от команды. Командные роли чтения дополнительно ограничены. | `controllers/{members,solves}.ts`, `models/{solve,ticket}.ts` |

### Целостность соревнования, утечки и устойчивость

| № | Проблема и исправление | Основные файлы |
|---|---|---|
| 10 | **Гонки при использовании приглашений:** несколько аккаунтов могли потратить последний use одновременно. Использование блокируется и проверяется в одной транзакции. | `controllers/members.ts` |
| 11 | **Гонки лимитов:** параллельные запросы обходили частоту submissions, maxSolves, лимит команды/вложений и использовали устаревший solve count для динамических очков. Записи одного соревнования сериализуются транзакционной блокировкой его строки с последующим повторным чтением. Идентификаторы с ведущими нулями блокируют ту же каноническую строку. | `services/http.ts`, `controllers/members.ts` |
| 12 | **Повторная оплата одной подсказки товарищами:** уникальность была только по пользователю. Добавлены отдельные уникальные ограничения для персональной и командной покупки; исторические дубликаты объединяются миграцией. Перехват конфликта теперь использует savepoint, а не оставляет транзакцию в failed state. | `controllers/hints.ts`, `migrations/002_security.sql` |
| 13 | **Обнуление штрафов за подсказки через удаление/пересоздание команды.** Удаление разрешалось, если не было solves, даже при купленных hints. Самостоятельные изменения состава/удаление после scoring activity ограничены; пустая команда с историей не удаляется автоматически. Управление капитаном требует актуального активного членства. Администраторы сохраняют модерацию. | `controllers/{teams,members}.ts`, `services/teams.ts` |
| 14 | **Поисковый оракул приватных описаний.** Некоррелированный EXISTS искал description во всех соревнованиях и влиял на публичные результаты. Поиск ограничен description текущей строки. | `controllers/competitions.ts` |
| 15 | **Обход заморозки через статистику.** Счётчики solves/submissions и динамические points оставались live. Применён freeze cutoff для обычных зрителей; live остаётся у уполномоченного staff. Публичная платформенная статистика исключает приватные соревнования и учитывает freeze. | `services/{tasks,competitions,scoring}.ts`, `controllers/platform.ts` |
| 16 | **Неограниченные попытки входа/потребление ресурсов.** Введены ограниченные по памяти per-IP окна: 30 auth-запросов и 600 API-запросов в минуту, 64 одновременных API-запроса и максимум две загрузки. Классификация учитывает matched route, поэтому дополнительные `/` не обходят auth-limit. X-Forwarded-For не считается доверенным. | `auth/security.ts` |
| 17 | **CSRF/MIME confusion.** Добавлена проверка Origin и Fetch Metadata на изменяющих запросах. Тип содержимого сравнивается точно, а не по вхождению `application/json` в произвольную строку. Легитимные JSON, URL-encoded и upload multipart сохранены. | `auth/security.ts`, `packages/thingamajig/src/chassis.ts` |
| 18 | **Долгие тела запросов удерживали транзакции.** Тела, включая multipart, теперь читаются с ограничениями до открытия транзакции и получения business locks. Есть deadline тела и HTTP/DB timeouts. Ошибки отключения idle/checked-out PostgreSQL-клиентов обрабатываются, не завершая весь процесс через необработанный EventEmitter error. | `packages/thingamajig/src/{chassis,spigot}.ts`, `apps/server/src/app.ts` |
| 19 | **Чувствительные данные в SQL-ошибках.** PostgreSQL detail мог включать значения конфликтующей строки. Клиент получает обобщённую ошибку, не сырые DB details. | `packages/thingamajig/src/spigot.ts` |
| 20 | **Условный выход через symlink в static root.** Проверялся только лексический путь. Проверяются канонические пути root и конечного файла. В runtime статический каталог read-only, что также исключает запись symlink через приложение. | `packages/thingamajig/src/chassis.ts`, `Dockerfile`, `compose.yaml` |
| 21 | **Небезопасные граничные значения.** Проверяется safe integer, отклоняется NUL, объектная схема читает только собственные свойства и создаёт результат без прототипа. Raw SQL literal дополнительно экранирует backslash независимо от PostgreSQL standard_conforming_strings. | `packages/thingamajig/src/gauge.ts`, `services/{http,sql}.ts` |

## Дополнительное укрепление

- В БД хранятся SHA-256 от случайных session tokens, а не готовые cookie.
  Смена сессии отзывает прежнюю сессию данного клиента. Миграция отзывает все
  старые сессии один раз; существующие scrypt-пароли совместимы.
- Cookie остаётся HttpOnly/SameSite=Lax; Secure и HSTS включаются через
  `COOKIE_SECURE=true` для HTTPS. Добавлены no-store, nosniff, frame protection,
  referrer policy. Для HTML разрешены скрипты своего origin и хеши встроенных
  скриптов; для API/загрузок действует ограничивающий CSP/sandbox.
- Сохранена принудительная выдача файлов как attachment, добавлены приватные
  режимы файлов/каталога и создание без перезаписи существующего storage key.
- Runtime-контейнер работает не от root, без Linux capabilities, с read-only
  root filesystem, ограничениями памяти/PID. Build tools отделены от runtime.
- Для новой БД создаётся отдельный НЕ-superuser приложения; DB-пароли случайны,
  небезопасный fallback DATABASE_URL удалён. Для существующих томов нужна
  отдельная миграция credentials/ролей — инструкция в README.

## Зависимости

До обновления `pnpm audit` сообщал **15 advisories**:
1 critical, 5 high, 6 moderate, 3 low. Большинство относилось к Astro и sharp;
среди них были XSS, SSRF и RCE в image optimization. Не все эти пути доступны
в данном статически собранном фронтенде, но оставлять такие зависимости нельзя.

- Astro обновлён с 5.18.2 до **7.4.2**; sharp — до **0.35.5**.
- Уязвимая optional-зависимость esbuild удалена из разрешённого графа; override
  не допускает версию ниже исправленной 0.28.1.
- Зафиксирован обновлённый `pnpm-lock.yaml`; frozen install проходит.
- Итоговый `pnpm audit`: **0 известных advisories** на момент проверки. Это не
  равнозначно отсутствию будущих или неизвестных уязвимостей.

Успешно выполнено:

1. `pnpm install --frozen-lockfile`.
2. `pnpm -r run build` — сервер, фреймворк и 29 страниц фронтенда.
3. Unit + HTTP/PostgreSQL регрессии: **25/25 passed, 0 skipped** (включая
   родительский интеграционный test). Подтверждены запрет pass-the-hash,
   параметризация SQL, read-фильтрация nested queries, изоляция ролей,
   недоступность revisions участникам, token binding, бан, корректность hints,

   CSRF/MIME, slow-body и восстановление после DB disconnect.
4. `astro check`: **0 errors, 0 warnings**, один информационный hint об уже
   существующем fallback `document.execCommand`.
5. `pnpm audit`: 0 advisories.
6. `docker compose config --quiet`, `sh -n` скриптов — успешно.
7. Production-only пакет из `pnpm deploy --prod --legacy`: успешные миграции и
   HTTP smoke `/api/health`, `/api/stats`, `/login/` с непривилегированным

Логи и JSON аудита приложены в `artifacts/validation/`.

### Что не проверено и ограничения

- Предоставленного чекера соревнования в каталоге нет. Проверены собственные
  сценарии реального API; идентичность поведения внешнего чекера не заявляется.
- Dockerfile не удалось собрать целиком: Docker Hub недоступен из окружения
  (`EOF`/ошибка получения anonymous token). Не удалось скачать PostgreSQL 17.
  Runtime-пакет проверен непосредственно на Node.js 26, интеграционные тесты —
  на доступном локальном PostgreSQL **14.1**. Проверка именно контейнеров с
  PostgreSQL 17 и сканирование CVE базовых образов остаются за окружением запуска.
- Лимиты в приложении per-process; при нескольких экземплярах нужны общие
  ограничения на proxy/Redis. Защита от распределённого DoS, дисковые квоты,
  TLS termination и резервное копирование требуют инфраструктуры.
- Сериализация записей на соревнование сознательно снижает параллелизм ради
  целостности. Для большой нагрузки потребуется более тонкая блокировка с теми
  же инвариантами. Тела запросов при этом НЕ удерживают DB-lock.
- Патч не отменяет уже состоявшуюся компрометацию. Из-за исходной SQL-инъекции
  и прежней superuser-роли при признаках атаки нельзя доверять старым ролям,
  токенам, данным, настройкам БД и файлам без отдельной проверки/восстановления.

## Развёртывание

См. `README.md`. Для attack–defence при обновлении **сохраните существующие тома,
данные и Compose project name**, не делайте `down -v`. Не меняйте значения флагов
и наград без необходимости восстановления после компрометации.
