Local hardening status (changes after commit 1b13614)

Implemented:
- Sensitive game reads require participation. Public game listings no longer offer
  an Open link for unrelated accounts. Waiting games can still be joined.
- Move version is optional for compatibility with original clients. When omitted,
  the loaded game version is used for the atomic actor/status/turn/version guard.
  Explicit stale versions still fail. Legacy requests do not prevent later replay.
- Account public keys are snapshotted per game. Create/join and key updates commit
  together; failed joins roll back the account-key update as well.
- Creation/join before key installation is supported again. POST /api/keys fills
  missing participant snapshots once and never overwrites initialized snapshots.
- Existing games snapshot CURRENT account keys once on migration. This cannot
  reconstruct an original key that was already overwritten before this patch.
- Browser private keys are archived on rotation so existing game snapshots remain
  usable in that browser. No recovery of previously lost private keys is possible.
- Games use before=<game_id>; moves/messages use after=<seq_or_message_id>.
  Each endpoint returns at most 100 records, with limit in [1,100]. Responses stay
  arrays. Messages now include id. The lobby has page navigation and chat polling
  uses incremental cursors; the visible chat retains the last 500 fetched records.
- Expired/revoked/legacy sessions are deleted in bounded batches every minute.
- HTTP request/body/header/idle timeouts and bounded bodies/headers are configured.
- Cross-origin browser writes are rejected unless explicitly allowed. A request
  body must contain exactly one JSON value.
- nginx records login/registration limit excesses in DRY-RUN mode. It does not
  reject requests with 429: logs showed one source address shared by many clients,
  and its ownership is unknown. Do not trust client-supplied forwarding headers.
- nginx forwards Host with its published port using $http_host; using $host had
  caused legitimate browser registration to fail the Origin check with 403.

Transport:
- Backend SESSION_COOKIE_SECURE defaults to true, independently of proxy TLS.
- Included compose explicitly defaults it to false for its plain-HTTP LOCAL setup.
  Production requires HTTPS and SESSION_COOKIE_SECURE=true. TLS certificates,
  external hostname, deployment policy and actual TLS termination remain UNKNOWN.
- SESSION_TTL defaults to 12h and is configurable. It is an absolute session life.

NOT completed / WAITING_FOR_USER (protocol-v2-001):
- Replacing the weak GF(251) key exchange and board encryption.
- Separating chat keys from board-derived secrets.
- Server-authoritative move calculation, including all agreed Go rules.
- Selecting a safe migration/read-only policy for legacy games and ciphertext.

These changes are deliberately not described as complete flag protection.
Legacy crypto still allows secret enumeration and key leakage from board data.
Checker and flag storage specification are unavailable.
