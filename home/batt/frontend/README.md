# Фронтенд «Морского боя»

React + TypeScript + Vite, react-router. Состояние — только встроенные средства React, сеть — нативные `fetch` и `WebSocket`, стили — обычный CSS. Оформление: шариковая ручка на тетрадном листе в клетку.

## Запуск

```sh
npm ci
npm run dev        # http://localhost:5173, /api и /ws проксируются на http://localhost:8080
npm run build      # проверка типов + сборка в dist/
npm run preview    # собранная версия, с тем же прокси
npm run lint
```

Адрес бэкенда для dev/preview-прокси можно сменить: `BACKEND_URL=http://host:port npm run dev`. В проде статику раздаёт nginx (см. `../nginx`), клиент ходит только на свой origin.

## Маршруты

| Путь | Экран |
|------|-------|
| `/` | логотип, грустный линкор, записка капитану и кнопки: «Играть» (→ `/lobby`) после входа, иначе «Вход» / «Регистрация» (→ `/login` с нужной вкладкой); в основном чанке, сессия проверяется без блокировки отрисовки |
| `/login` | вход и регистрация; после входа возвращает туда, куда шли (например, по ссылке-приглашению) |
| `/lobby` | игра с ботом, PvP-комната с кодом и ссылкой, вступление по коду, история партий, выход |
| `/game/:id` | расстановка, бой, журнал, чат; не участник видит только публичную информацию |

`/lobby` и `/game/:id` закрыты `RequireAuth`: 401 от `/api/me` (или от любого запроса) ведёт на `/login`. Login, Lobby и Game грузятся лениво.

## Структура

```
src/
  api/      types.ts — единый источник правды о контракте (HTTP и WS); client.ts — fetch с credentials;
            auth.ts, games.ts, fleet.ts — ручки; errors.ts — перевод ошибок сервера
  ws/       socket.ts — один сокет на партию, реконнект с бэкоффом; useGameSocket.ts — хук
  auth/     AuthContext, RequireAuth
  pages/    Home, Login, Lobby, Game
  game/     Board, Cell, boardModel (клетки из журнала выстрелов), FleetSetup, fleet (подсказки расстановки),
            gameReducer (применяет события сервера), BattleBoards, TurnBanner, ShotLog, GameOverCard, Chat,
            GameHistory, InviteBox, ShipView, shipSprites (длина + настроение → картинка)
  ui/       InkDefs (общие SVG-фильтры #ink/#ink-fine и символы отметок), rough.ts (seed-штрихи),
            SketchBorder, Button, Field, Paper/Card, Note, PageLoader, icons/
  styles/   tokens.css (палитра, клетка, шрифт), global.css, ui.css, login.css, lobby.css
```

При расхождении с бэкендом правка делается в `src/api/types.ts` и модулях `src/api`, `src/ws` — компоненты сами `fetch` не вызывают.

## Принципы

- Сервер авторитетный: клиент не знает чужую расстановку и не считает правила. Попадания, ход, конец партии и автопометки вокруг потопленного рисуются по `state`/`shot_result`/`game_over`. Проверки в `game/fleet.ts` — только подсказки при расстановке.
- Производительность: клетки — memo-div с `data-s`, вид задаёт CSS; один обработчик клика на доску; линии поля — один градиент; отметки выстрелов — `<use>` на общие символы; «дрожащие» пути генерируются по seed и кэшируются. Свой выстрел не перерисовывает своё поле.
- Фильтр «чернил» статичен и висит на псевдоэлементах рамок и на мелких иконках; на большие области не анимируется. `prefers-reduced-motion` отключает анимации.
- Чат: текст выводится только как текст (React экранирует), лимит 500 символов как на сервере; отправка по WS, запасной путь — HTTP.
- Ники: сервер присылает `player1_name` / `player2_name` (партия и `state`) и `opponent_name` (история); `game/players.ts` превращает их в подписи — свой ник, ник соперника или «Бот». Формулировки с ником — без рода.
- После партии сервер раскрывает `enemy_ships`: уцелевшие корабли соперника рисуются тусклыми и медленно мерцают (только `opacity`); до конца партии поле пустое.
- Анимации выстрела: взрыв при попадании (крупнее при потоплении), всплеск при промахе. Только свежие события, только `transform`/`opacity`, эффект убирается по таймеру (в фоновой вкладке не копится); при `prefers-reduced-motion` не проигрывается.

## Корабли

Корабли нарисованы «шариковой ручкой»: тонкие дрожащие штрихи, двойные обводки, штриховка, нарочито смешные детали. Это готовые SVG в `src/assets/ships/doodle/` (вид сбоку, клетка = 100 единиц). Их генерирует вспомогательный скрипт `tools/ships/draw_ships.mjs` в корне репозитория (`node tools/ships/draw_ships.mjs`); он лежит только локально — `tools/` в `.gitignore` и `.dockerignore`, в репозиторий и сборку не входит. Стволы — толстые залитые «трубки», чтобы читались в клетке 34 px. У каждого корабля три настроения (`ship{len}-{mood}.svg`):

- `ok` — целый: весёлый, стволы бодро задраны, дым кудряшками;
- `hurt` — подбит: стволы обвисли, грустная бровь, слёзы ручьём, флаг поник (у однопалубного нет — тонет с первого попадания);
- `dead` — потоплен: пробоина, из неё течёт топливо в лужу, крестик на глазу, язык наружу.

На своём поле настроение считается по выстрелам соперника; на поле соперника видны только потопленные — всегда `dead` (размер и положение приходят в `shot_result.sunk`). Выбор картинки — `src/game/shipSprites.ts`.
